# 判定に迷ったとき

## `[suggestion]` / `[nit]` で承認を保留しない

定義として**止めないもの**なので、それを理由に承認を保留すると、
**ラベルは「止めない」と言いながら機構が止める**ことになる
（承認を要求する仕組みの下では、承認を出さないことが実質のブロックになる）。

**判断を含む指摘は原理的に尽きない。** 尽きないもので承認を保留しない。

## `[ask]` だけが例外

判断がつかないから聞いている状態で承認（＝懸念なし）を出すのは、**信号として嘘になる**。
答えが来たら承認を出し直す。

**ただし `[ask]` が付いていれば止める、ではない。** 止めるのは**答えで結論が変わる**ときだけ。

| | 例 | 判定 |
|---|---|---|
| **確認**（読みが立っている） | 「〜という理解で合っていますか」「許容範囲という想定で合っていますか（任意です）」 | **止めない** |
| **判断不能**（答えで結論が変わる） | 「〜であれば対策が失われる経路はなく解消です」「どちらを採るかはこちらでは決めません」 | **`COMMENT`** |

読みを立てたうえでの確認は、承認を保留する理由にならない。

## 自分の PR

**`APPROVE` も `REQUEST_CHANGES` も出せない**（どちらも 422 で落ちる）。
`COMMENT` を使い、**本来の判定を本文の冒頭に書く**。詳細は `github.md`。
