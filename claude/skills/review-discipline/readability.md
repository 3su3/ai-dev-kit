# 読まれるレビューにする

**長さの規則では決まらない。** 「2〜5行」と書いてあっても 2,000 字になる（実測）。
決めるのは次の3つ。

## 1. 冒頭2行で「何をすればいいか」

経緯・前置き・調査の手順から始めない。**作者が最初に知りたいのは、自分が何をするか。**

```
悪い: 「Claude と Kiro の2つのレビューを突き合わせて統合した。差分6ファイルに加えて…」
良い: 「直すのはドキュメント1行だけ。コードの変更は要らない。」
```

判定の理由はその後ろに 2〜4 行。**根拠の詳細は本文に置かない。**

## 2. 1文に1つ

**根拠・条件・反証を1文へ詰めない。** 詰まった文は、読み手が構造を解いてから読むことになる。

```
悪い: 「Kiro の『CLI が PATH に無いとテストが落ちうる』は、prod-runtime に A（`x:198`）・
       base/dev に B（`:20`）が入っており、既存の C が同じ呼び出しで本番配備済みのため落とした。」
良い: 「Kiro の『CLI が PATH に無い』は落とした。
       - prod-runtime に A（`x:198`）、base/dev に B（`:20`）がある
       - 既存の C が同じ呼び出しで本番配備済み」
```

**100 字を超えたら、箇条書きに割れないかを疑う。**

## 3. 根拠はインラインへ、過程は畳む

| 情報 | 置き場 |
|---|---|
| **作者が直すもの** | インラインコメント（行に付く） |
| 判定と件数 | 総評の冒頭 |
| **調査の過程・再現手順** | インラインの中、または `<details>` で畳む |
| 別チケットの提案 | **別コメント**。総評に混ぜない |

**総評は「読まなくても困らない」ものを持たない。** 作者が読む順は
「自分は何をするか」→「なぜか」→（必要なら）「どう確かめたか」。

## クロスレビューのとき

**2人の差は1行で足りる。**

```
- クロスレビュー: 2人。両方 7 / 片方だけ 9 / 格付けが割れた 2
```

**相違の理由を総評で展開しない。** 割れた指摘のインラインに書く。
片方が落とした指摘の根拠も同じ。
