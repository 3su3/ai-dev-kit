# どのモデルを使うか

**基準は2つ。間違えたときのコストと、正解が一意かどうか。差分の行数ではない。**

リスク分類（`risk-policy.md`）の直後に見る。実装に入ってからでは選び直せない。

## 既定

| 作業 | 性質 | モデル |
|---|---|---|
| 誤字・機械的な置換・生成物の反映 | **正解が一意。** やり直しが安い | 軽い |
| 通常の実装（機能追加・既存挙動の修正） | 判断は要るが範囲が限定されている | 中 |
| 調査・原因特定・設計・計画 | 広く読んで分岐を評価する | 重い |
| レビュー | **見落としのコストが高い。** 判断の塊 | 重い |
| 高リスク（認証・DB・本番・金額） | 間違いが非可逆 | 重い。**ここで節約しない** |

**迷ったら重い方。** 軽くして失敗したときのやり直しは、最初から重いモデルを使うより高い。

### 「判断を含むか」の見分け

レビューの指摘数で後から分かる（実測）。

| 性質 | 指摘数 | 正解 |
|---|---:|---|
| 機械的 | 0〜1 | 一意。合否だけ |
| 判断を含む | 4〜16 | **「別の判断もありうる」が尽きない** |

着手前に分けるなら「**自分以外の誰かが同じ結論に辿り着くか**」を問う。
辿り着かないなら判断を含む作業で、重いモデルの側。

## 面ごとの指定のしかた

| 面 | どこで決まるか | 粒度 |
|---|---|---|
| Claude Code | `/model`。サブエージェント定義の `model:` | セッション／サブエージェント |
| Kiro | `kiro-cli chat --model <名前>`。agent 定義の `model` | **その回／agent ごと** |
| Codex | `~/.codex/config.toml` の `model` | 全体で1つ |

Claude 系の重い順: `opus` > `sonnet` > `haiku`。

**記録に残る指定を使う。** 何が選ばれたか残らないと、後から良し悪しを確かめられない。

### Kiro の制約（2026-10-21 実測）

- **既定の agent にモデルを固定できない。** 設定キーが無く、`~/.kiro/agents/kiro_default.json`
  を置けばモデルは変わるが、**道具立てごと置き換わる**（ツール集合の指紋が変わる）。
  組み込みの既定を再現できないので、やらない
- `model` を省くと `auto`。**何が選ばれたか記録に残らない**（`modelId: "auto"` としか出ない）
- **段が全部あるとは限らない。** 契約や時期で使えるモデルは変わる。
  **軽い段が無いこともある**ので、その場合はこの表の「軽い」を一段上へ読み替える
- 重いモデルを使いたい回は `--model <名前>` と明示する。**これは記録に残る**

**使えるモデルは一覧で引けないことがある。** その場合は名前を指定して試し、
`not available` が返るかで判定する（無効な名前はエラーになるので区別できる）。

結果として、Kiro の既定（レビューが走る面）は `auto` のままになる。
**モデル選択がそのまま効くのは Claude と Codex。**

## この既定は測っていない

**上の表は、作業の性質から立てた初期値であって、実測の結論ではない。**
モデル間の比較をするには、何を使ったかが記録に残っている必要があるが、
現時点では Kiro の既定が `auto`、Claude が1種類のみで、比較の材料が無い。

**外れている合図:**

- 軽いモデルに任せた作業が、やり直しになる／レビューで差し戻される
  → その作業は「機械的」ではなかった。1段上げる
- 重いモデルを使った作業で、指摘が 0〜1 件しか出ない
  → 機械的な作業だった。1段下げられる

合図が出たら、この表の行を**その作業ごと**動かす。表全体を上げ下げしない。
