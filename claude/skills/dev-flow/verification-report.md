# 実機で確かめたあとの報告

**結論を1語目に置く。** 読む人が最初に知りたいのは「進んでよいか」だけ。

```
実機確認（<環境> / 反映の確認: <何で確かめたか>）:
 1. 結論            **問題なし** / **懸念あり** のどちらかを必ず書く
 2. 確かめたこと    1行
 3. 確かめていないこと  1行。**「無し」と書けるのは、範囲を言い切れるときだけ**
 4. 懸念            1行。結論が「懸念あり」のときだけ
```

## 反映されたことを先に確かめる

**古い版を見て「問題なし」と言うのが、この段で一番多い事故。**
デプロイが届いていないと、**画面も出力も「何も変わっていない」という正しい見た目**になる。

**何で反映を確かめたかを、報告の頭に書く。** 書けないなら、確かめていない。

- 配備されたものの版が、手元の変更と一致するか（リビジョン・ハッシュ・ビルド番号）
- 変更で初めて現れるもの（新しい経路・新しい文言・新しい列）が、実際に現れるか

**「差分が無い」を成果として報告しない。** 反映されていない場合と区別がつかない。

## 「問題なし」と書く前に

- **その画面・その経路を、変更が実際に通ったか。** 通っていない経路を見て「問題なし」と言わない
- **データがあるか。** 件数 0 の一覧は、壊れていても正常に見える
- **確かめていない範囲を黙らせない。** 3 に書く

## 「懸念あり」のとき

**止めるか進めるかは、人が決める。** 判断を代わりにしない。
懸念は**1行で、何が起きうるかを具体的に**書く。「念のため」は書かない。
