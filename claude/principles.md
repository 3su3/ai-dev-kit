# 常時の原則

**ここは毎回読まれる層。増やすと全部の効きが落ちるので、増やす前に1つ落とす。**

場面が限られるものは skill（②層）へ、再発が数えられるものは検査の道具（③層）へ送る。

- **網羅性を主張するときは、何と突き合わせたかを書く。** 「全部できた」「残りは無い」と言い切らない
- **数える対象の集合を手で作らない。** 「この集合はどこから来たか」に、道具の定義関数・API の列挙・規約のリストで答えられること。**答えられないものは手で作っている。**これまで漏れたのは接頭辞 / grep の範囲 / 時点 / 値の括り方 / 環境。**毎回違う形で来る**
- **自分の検証に偽の緑が無いかを、指摘される前に自分で探す。** 常に真になる条件・取得失敗と正常が同じ顔になる出力を疑う
- **テストが赤になることを、実装を壊して確かめてから報告する。** 通ったことだけでは何も言えない
- **同じ指摘が3回続いたら、ケースを足さず主張を狭めるか解き方を変える。** 近似を足す限り次の反例が出る
- **主張・観点・規約は1箇所に置く。** 2箇所に持つと、必ず古い方が生き残る
- **観測した値を書き写さない。** コメント・テストデータ・ドキュメントには架空値だけを使う

---

**ここに入れるのは、他プロジェクト・他の人にも通じるものだけ。**
流儀で変わるもの（コミット規約・PR の出し方・進め方）は `local/preferences.md` へ。
