# 実装計画: 初回共有前の Public-ready 判断

> **状態: Plan レビュー・実装承認待ち** — [Issue #10](https://github.com/3su3/ai-dev-kit/issues/10) に基づく。実装は未着手。

# 1. 概要

## 背景

[PR #9](https://github.com/3su3/ai-dev-kit/pull/9) の初回 CI で `verify-confidential.py` が失敗した。修正後の CI は成功したが、初回共有前に判断と検査を行う手順が明瞭かを確認する必要がある。

## 目的

このリポジトリへの貢献で、最初の外部共有前に Public-ready の判断と既存検査を行うタイミングを明確にする。

## 対応内容

調査結果を本 Plan に残し、承認後に `CONTRIBUTING.md` の既存規約へ短い手順を加える。新しい検査や導入先向けの push 規則は追加しない。

# 2. ビジネス向けサマリー

## 変更内容

初回 push と Draft PR 共有の前に、内容の公開可否を判断し、既存検査を実行することを明記する。

## Before / After

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 判断時点 | 持ち込み前の判断と変更後の検査はあるが、初回外部共有との関係が明示されていない | 初回外部共有前に判断・検査結果を確認する |
| 失敗時 | 疑義があれば停止する原則はある | 検査失敗を機密確定とみなさず、原因と公開可否を判断できるまで共有を止める |

## 業務への影響

このリポジトリの貢献者にだけ適用される。導入先の規約は変わらない。

## 影響しないこと

既存 CI、公開設定、履歴修正の承認権限は変えない。

# 3. 現状調査

## 現在の実装

- `CONTRIBUTING.md` は Public-ready と可搬性を要求し、Plan を Draft PR で共有する。
- `docs/principles/public-ready.md` は不明な素材の持ち込み前停止を要求する。
- `AGENTS.md` は変更後の検査を指示し、`README.md` は既存検査の実行方法を示す。
- `tests/verify-confidential.py` は作業ツリーの追跡ファイルと `git rev-list --all` で得た履歴を検査する。検出語は限定的であり、合格は公開可否の保証ではない。
- `tests/verify-portable.py` は普遍の層の一部を静的に調べ、可搬性の人間判断を代替しない。

## 関連する実装

- [PR #9 の初回 CI](https://github.com/3su3/ai-dev-kit/actions/runs/41207819434) は上記の機密検査で失敗した。[修正後 CI](https://github.com/3su3/ai-dev-kit/actions/runs/41208592554) は成功した。
- PR 本文とコメントから、Plan 修正、Human 許可を得たブランチ履歴更新、その後の再レビューは確認できる。
- 初回 push 前に担当者が規約を読んだか、ローカルで検査を実行したかは、閲覧可能な PR・CI 記録から確認できない。未確認であり、違反とは判断しない。
- GitHub に残る旧 PR 参照の完全削除も確認できない。

## 問題点

作業ツリーを直しただけでは履歴の検出は解消しない。CI の検出時点は初回共有後であり、規約到達・事前実行・失敗時停止の証拠にならない。

# 4. 実装方針

## 検討事項

このリポジトリ固有の手順を正本に一度だけ置く。機械の検出結果と Human による公開可否判断を分ける。

## 方針候補

### 案A

#### 内容

`CONTRIBUTING.md` に初回共有前の判断と検査の順序を短く追記する。

#### メリット

全貢献者が参照する正本に置ける。既存の道具を使える。

#### デメリット

文書だけではエージェントの遵守を保証できない。

### 案B

#### 内容

既存規約で十分として変更しない。

#### メリット

軽微な変更への負担を増やさない。

#### デメリット

初回共有前という時点は曖昧なまま残る。

### 案C

#### 内容

新しい検査または push フックを加える。

#### メリット

実行の自動化を図れる。

#### デメリット

既存検査が検出した今回の原因に対して過剰で、環境ごとの制約も増える。

## 採用予定の方針

**Minimal。案A。** `CONTRIBUTING.md` のみに手順を加える。

## 採用理由

Issue が問うのは検査の実行時点であり、CI 自体は検出できた。追加が重複になったり、軽微な変更の負担が効果に見合わなければ文言を縮小または撤退する。
