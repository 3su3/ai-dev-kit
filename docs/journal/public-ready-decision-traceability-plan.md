# 実装計画: Public-ready と Decision Traceability

> **状態: 完了** — PR [#4](https://github.com/3su3/ai-dev-kit/pull/4) でマージ済み。成果物は `CONTRIBUTING.md` と `docs/principles/public-ready.md`。

> この行は実装・撤退のたびに更新する。更新されていない状態行は、書いた時点で凍っているだけで現状を表さない。


## 1. 概要

### 背景

Private 運用中でも公開可能な情報だけを扱い、変更理由を後から追えるようにするという、Human と合意した二原則を `3su3/ai-dev-kit` の規則へ反映する。

### 目的

貢献者とエージェントが、情報の持ち込み可否、理由の記録先、判断できない場合の停止先を同じ規則から確認できるようにする。

### 対応内容

共通規則を `CONTRIBUTING.md` に置き、Public-ready の判断詳細を専用文書に置く。README とエージェントの入口は要約と参照だけにし、PR テンプレートは記録を促す補助とする。

## 2. ビジネス向けサマリー

| 項目 | 変更前 | 変更後 |
| --- | --- | --- |
| 情報の持ち込み | `terms/` の業務語彙を除外する説明などが点在 | このリポジトリへの貢献に共通の Public-ready 基準を明示 |
| 変更理由 | dev-flow の Plan と既存の履歴に依存 | 人間・AIを同じ基準で扱い、Issue・PR・コミット・設計文書のいずれかから追跡可能にする |

業務リポジトリ、導入先プロジェクト、公開設定は変更しない。Public 化は別の明示承認を必要とする。

## 3. 現状調査

- ローカルの作業ツリー名は `dotfiles` だが、origin は `3su3/ai-dev-kit`。調査開始時は `main` で未コミット変更なし。計画記録用にローカルブランチ `docs/public-ready-decision-traceability-plan` を作成した。
- `README.md` は普遍的なハーネスと `local/`・`terms/` の分離、配布経路を説明する。`CONTRIBUTING.md`、`docs/principles/`、PR テンプレート、リポジトリ内の `AGENTS.md` は追跡ファイルに存在しない。
- `claude/principles.md` は常時配布する短い原則の正本で、規約の重複を避けるよう求める。`dev-flow/risk-policy.md` は機密の疑義で停止し、プロジェクト固有の規約と承認を優先する。`plan-template.md` は変更理由・採用理由を記録する。二原則と一部重なるが、Public-ready の対象範囲と、人間を含む変更理由の記録先は明文化されていない。
- `bin/harness-sync` は `claude/principles.md` を Codex の `~/.codex/AGENTS.md` に生成し、Kiro の `~/.kiro/steering/00-principles.md` に生成する。Claude Code は利用者の `~/.claude/CLAUDE.md` からの明示 import が必要で、`install.sh` は skills の symlink のみを自動作成する。正本の変更だけで全環境への配布完了とは主張しない。
- 既存の秘密情報が現在の追跡ファイルと Git 履歴に存在することを、値を表示せず確認した。今回の文書導入で既存履歴が公開可能になるわけではない。
- 対象は文書と配布入口であり、クラス・API・DB・CSS の依存調査は該当しない。参照元は README、dev-flow、`harness-sync` と既存の検証記録で確認した。

## 4. 実装方針

### 検討事項・方針候補

- 案 A: 各エージェント向けファイルに全文を複製する。配布は単純だが、規則が分岐する。
- 案 B: `CONTRIBUTING.md` に共通の義務、`docs/principles/public-ready.md` に詳細を置き、各入口から参照する。既存の単一正本・短い常時原則に合う。

### 採用予定の方針と理由

**Minimal、案 B。** このリポジトリへの貢献に範囲を限定する。`claude/principles.md` には「このハーネスを変更するとき」の確認・停止と参照先を短く入れ、既存項目との統合で常時原則を肥大させない。Codex・Kiro への反映には既存の `harness-sync` を使い、配布機構や dev-flow の承認規則を増やさない。PR テンプレートは理由の記録先を尋ねるだけにし、新規 Issue や Plan を一律必須にしない。

Public-ready の詳細には、仕事・顧客・他リポジトリの機密情報、権利関係が不明な素材を持ち込まないこと、疑義は Human に確認すること、実際の Public 化には別の明示承認が必要なことを置く。Decision Traceability は追加・変更・削除の理由が既存の Issue・PR・コミット・設計文書などから追えることを共通規則として置き、重複記録を求めない。

### dev-flow との優先関係

`CONTRIBUTING.md` は **このリポジトリへの貢献に適用する内容の基準**、dev-flow は **調査・計画・承認・実装・検証の手順**とする。今回の二原則は dev-flow の Plan や Human 承認を省略しない。記録先は dev-flow と対象リポジトリの規則に従い、既存の記録から理由を追えるなら同じ説明を別の Issue に複製しない。規則が衝突する、承認者や適用範囲が不明な場合は実装を止めて Human に確認する。

## 6. 影響範囲とリスク

**高リスクとして扱う。** 情報公開と秘密情報の判断、全エージェントに届く原則に関わるため。文書変更自体に実行時コードの変更はないが、今後の作業判断に影響する。

- `CONTRIBUTING.md` はこのリポジトリの貢献者へ適用する。導入先プロジェクトの Issue・PR・Plan・承認・機密規則を上書きしない。エージェント配布文にも適用範囲を明記する。
- Claude Code には既存の `~/.claude/CLAUDE.md` からの import を通じて、Codex には `harness-sync` が生成する `~/.codex/AGENTS.md`、Kiro には同コマンドが生成する `~/.kiro/steering/00-principles.md` を通じて入口を届ける。同期の実行は別に確認する。配布先の規則と衝突した場合も自動で優先順位を決めず Human に確認する。
- 新規の文章・画像・ログ・例・リンク先などについて、機密情報や権利上の問題がある、または判断できないときは、その素材の追加、コミット、PR 投稿、同期を止める。値や内容を確認依頼に貼らず、安全な概要だけで Human に判断を求める。既に存在する問題を見つけた場合も、この変更で解決済みと扱わない。
- 既存の秘密情報の値は表示・転記・計画への記載・コミットをしない。既存ファイル・履歴の対処は別の承認された作業とし、今回の完了を Public 化可能の証明にしない。
- Claude Code の実際の import 状態と Codex・Kiro の同期状態は環境依存。同期は実装後の別手順として実施可否を確認し、未配布を成功扱いしない。

## 7. テスト計画

- 正常系: 文書間リンク、適用範囲、二原則の要件、PR テンプレートが既存の理由記録への参照を許すことをレビューする。`harness-sync --dry-run` で生成対象を確認する。
- 異常系: 権利不明の素材、機密か不明な情報、理由の参照先がない変更、導入先の独自規則との衝突で、Human 確認または対象リポジトリの規則優先に至る文面かをシナリオで確認する。
- 境界値: 誤字修正を含む軽微な変更でも理由を追えるが、新規 Issue を要求しないこと、Private のままでも Public-ready を適用することを確認する。
- リグレッション: `tests/verify-dev-flow-risk.py`、`harness-sync --dry-run`、差分レビュー。実際のエージェント動作は静的確認だけで保証しない。新しい機械検査を追加する場合は、意図的に違反を入れて赤になることも確認する。
- 変更理由の追跡: 差分中の追加・変更・削除について、PR 本文か参照された既存記録から「なぜ」をたどれるかをレビューする。PR テンプレートの記入だけを根拠に成功とはしない。
- ロールバック: 配布前は対象の文書差分を戻す。配布後は先にソースの変更を戻し、Codex・Kiro は既存の `harness-sync` で生成物を再同期する。Claude Code は import 元を戻した状態で再読を確認する。手書き領域や導入先プロジェクトのファイルは触れない。秘密情報の既存ファイル・履歴の対処はこのロールバックに含めない。
- 計画作成段階ではテスト・同期を実行しない。
