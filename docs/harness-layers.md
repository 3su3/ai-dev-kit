# 個人ハーネスの3層

auto-memory は「思い出す」装置で、「守らせる」装置ではない。memory に書いてあったのに
4回繰り返した事例（`color-token-needs-usage-not-just-name`）がある以上、想起だけでは再発は止まらない。
増やす方向には上限があるので、置き場を効き方で分ける。

| 層 | 置き場 | 効き方 | 入れるもの | 入れないもの |
|---|---|---|---|---|
| ① 原則 | `claude/principles.md` → `~/.claude/CLAUDE.md` から `@` で import | 毎セッション必ず読まれる | **5〜10行だけ** | 場面が限られるもの。増やすと全部の効きが落ちる |
| ② 型 | `claude/skills/<name>/SKILL.md` → `~/.claude/skills/` | description で自動発火。**セッションの入り口で1回**（実測） | 「いつ発火するか」が1文で言えるもの | 発火条件が言えないもの／途中で確実に効かせたいもの |
| ③ 装置 | `bin/` のスクリプト、hooks | 機械が止める・警告する | **再発回数が数えられているもの** | 1回しか起きていないもの |

auto-memory は捨てない。**まだ型になっていない観察のバッファ**として残し、再発が確認できた時点で
②③へ昇格させる。昇格したら memory 側は「③の◯◯が見ている」と1行に縮める。

## 効いているかを測る

層に置いただけでは効かない。**「書いた」と「届いた」と「守られた」は別物で、
到達していて遵守していないことがある。** 測り方は [ハーネスが効いているかの測り方](measuring-a-harness.md)。

とくに①層は、**増やすほど効かなくなる**（実測。常時読みを 9,870 字足したら、
足した側に書いていない指示の遵守が 6/6 → 2/6 に落ちた）。冒頭の「増やす前に1つ落とす」は
文言ではなく測定の結論。

## ③に入れるときの作法

- 警告は実行可能にする。直し方を1コマンドで書けないなら、その警告は出さない
- チーム全体に効くもの（pre-commit 等）は、合意が取れるまでブロックせず警告に留める
- 対象の集合を手で並べない。glob・grep で機械的に決める

## 棚卸し: `bin/claude-memory-stocktake`

memory ディレクトリを走査し、**ファイルから数えられる事実だけ**を列にする。昇格先そのものは決めない。

| 列 | 何を数えているか | 何を証明しないか |
|---|---|---|
| `再発` / `強` | 本文中の「N回やった」等。`強` は数字で書いてあるもの | `強` が無い行は弱い根拠。**同じ集計に混ぜない** |
| `発火形~` | description に場面語（〜とき/〜前に）があるか | **近似**。②へ振れるかの判断ではない |
| `固有語` | `terms/<slug>.txt` の語彙との一致数 | 0 なら普遍的な手法の「候補」。語彙は手作りなので `--why` で一致語を確認する。**語彙ファイルが無ければ判定せず、その旨を出す** |
| `被link` | 他の memory から `[[name]]` で参照された数 | 中心性の指標。正しさではない |

```bash
claude-memory-stocktake --sort recur --md     # 再発の多い順
claude-memory-stocktake --sort inlinks --md   # 参照の多い順（①の候補）
claude-memory-stocktake --why <name>          # 1件の全列の根拠を出す
```

## 引き上げの合図

memory を ②③ へ上げるのは、**放っておくと誰も思い出さない**。合図を道具にする。

```bash
harness-status          # 前回見た時点からの差分
harness-status --mark   # いまを基準として記録する
```

見るのは **「再発が増えた memory」**。1回目は観察、2回目から「同じことが起きている」
という証拠になる。そこが ③ へ上げる線。

**先回りで全部を型にしない。** 使われない文章が増えるだけで、①層の効きが落ちる。
実際に踏んだものから1件ずつ上げる。

### 引き上げ先は3つある

**`harness-status` は固有のものも出す。** 出たものを全部このリポジトリへ入れてはいけない。

| 出たもの | 行き先 |
|---|---|
| **普遍**（他プロジェクト・他の人にも通じる） | **このリポジトリ**（②型 or ③装置） |
| **プロジェクト固有**（社内用語・環境名・特定の運用に依存） | **そのプロジェクト側**（`.claude/skills/` や `bin/`） |
| 判断がつかない | **memory のまま**。無理に動かさない |

このリポジトリは**公開前提**なので、固有のものを持ち込むと後から剥がすことになる。
[Public-ready 原則](principles/public-ready.md)と[README の「何を入れるか」](../README.md)が正本。

**迷ったら入れない。** 公開前に剥がすより、必要になってから入れるほうが安い。

#### 固有かどうかの見分け

`claude-memory-stocktake` の「固有語」列が 0 でも**普遍とは限らない**。語彙は手で並べたもので、
そこに無い固有名は素通りする。**要約（`description`）を読んで、他のプロジェクトでそのまま
通じるかを見る。** 通じないなら固有。

実測では、`description` に固有語を含むものが **110 件中 37 件（33%）**あった。
「原則は普遍だが根拠が固有」が 51 件（46%）で、これは**一般化してからでないと入れられない**。
